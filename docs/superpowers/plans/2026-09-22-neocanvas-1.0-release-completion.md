# NeoCanvas 1.0 Release Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce an evidence-backed NeoCanvas 1.0 iPad release candidate from the existing `ipad-gestures-phase1` branch without expanding product scope or weakening compatibility and safety behavior.

**Architecture:** Treat the existing application and CI workflow as the release system. Validate the current behavior through its focused shared tests and release-contract script, fix only reproducible release blockers with regression tests, then run one ordinary fast-validation commit followed by one same-tree `[ipad]` checkpoint. Physical-device checks remain explicitly separate from simulator and build evidence.

**Tech Stack:** Kotlin Multiplatform, Compose Multiplatform, Swift/iOS, Gradle 8.14.4, Python 3 release verifier, GitHub Actions, Xcode 26/macOS 26 runner.

**Spec:** `docs/superpowers/specs/2026-09-22-neocanvas-1.0-release-completion-design.md`

## Global Constraints

- Work only in `neoworkssuite/Canvas-Mac` on `ipad-gestures-phase1`.
- Fetch and compare with `origin/ipad-gestures-phase1` before every repository write; preserve and inspect concurrent commits.
- Never force-push, reset to an older checkpoint, or replace the application.
- Preserve compatible `.neocanvas` loading, recovery safety, atomic iPad writes, Gallery trash semantics, the real locked white Background layer, and active raster Layer 1.
- Preserve the Swift `URLSession` update bridge and App Store-mediated update installation.
- Keep version `1.0.0`, build `1`, bundle ID `com.neoworksuite.neocanvas`, and iPad-only distribution unless App Store upload work explicitly increments the build number.
- Add no unrelated features, presets, or redesign work.
- Mark physical-iPad checklist items only from physical-iPad evidence supplied by the human tester.

## Review Focus

- A newer remote commit appearing during the release pass must be inspected and incorporated without discarding either side.
- A green older `[ipad]` run must not be presented as validation of a newer release-candidate tree.
- A failed or cancelled GitHub job must retain its real conclusion and block the corresponding checklist item.
- A documentation-only `[ipad]` checkpoint must have the same Git tree as its fast-green parent.
- Simulator results must not mark Apple Pencil, touch ergonomics, Files interaction, or export-opening checks as physically accepted.
